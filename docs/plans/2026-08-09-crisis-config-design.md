# 全局动态危机分级与旧术语清洗设计

## 目标

在不修改 IndexedDB 既有字段和历史数据的前提下，为系统增加可配置的危机等级解释层，支持“一级最高危”和“三级最高危”两种地区口径；同时统一全系统下拉选项、Badge、概览统计和报告导出文案。

## 核心设计

- `useCrisisConfigStore` 负责保存 `severityDirection` 与三档等级别名，持久化到 `localStorage`。
- 学生和咨询记录继续使用现有 `level_1/2/3`、`red/orange/yellow`、`riskLevel` 等兼容字段；Store 根据方向计算严重度排序、颜色和显示文案。
- `desc`：`level_1` 为红色最高危，`level_2` 为橙色中危，`level_3` 为黄色低危。
- `asc`：`level_3` 为红色最高危，`level_2` 为橙色中危，`level_1` 为黄色低危。
- 所有表单、学生卡片、概览统计、周/月报和单人卷宗均通过同一 Store 读取 Badge 元数据，避免局部口径漂移。

## 交互与兼容

- 首次启动引导增加评级体系步骤，系统设置提供同样的实时配置入口。
- 用户切换方向或修改别名后，当前页面和后续导出立即使用新文案。
- 旧数据不迁移、不重算、不删除；没有配置时回退到 `desc` 和“重大/严重/一般/正常”。
- 概览删除重复的“待办与预警提醒”卡片，只保留 KPI 与危机分布统计。

## 验证

- 检查 `desc/asc` 两种方向的下拉顺序、颜色、排序与报告文案。
- 运行 `npm run build` 与 `git diff --check`。
- 打包 Windows NSIS 与 portable 版本，版本号更新为 `1.1.1`。
