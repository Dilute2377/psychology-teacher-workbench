# 2026-08-08｜安全备份、Mock 压测与恢复出厂设计

## 目标

在不上传数据、不改变现有本地数据归属的前提下，新增 500 人 Mock 压测、仅清理 Mock、恢复出厂、AES-256-GCM 加密备份、首次安全设置、Electron 静默落盘与自动备份。

## 方案选择

1. 浏览器下载：实现简单，但无法可靠地在后台写入自定义目录。
2. Electron IPC + 主进程文件写入：主进程负责目录选择和写文件，渲染进程只通过白名单 API 调用；Web 环境回退为标准下载。
3. 渲染进程直接使用 Node：不符合 context isolation 安全边界，放弃。

采用方案 2。主进程通过 `save-backup-file` 和 `select-backup-folder` 提供最小能力面，preload 只暴露对应方法。

## 数据与流程

- AES-256-GCM 使用 PBKDF2 100,000 次派生密钥；备份载荷包含版本、盐、IV 和密文，导出扩展名为 `.mindbag`。
- 备份导出集中读取当前 Dexie 全表和系统配置，自动备份与手动备份共用同一导出函数。
- Mock 学生、咨询、普查、工作留痕使用统一 `isMock` 标记，批量写入使用 Dexie 事务和 `bulkAdd`。
- 恢复出厂清空当前数据库全部表，保留数据库结构和必要初始化配置；清理 Mock 只删除带标记的记录及其关联记录。
- 首次安全设置使用 `localStorage` 保存完成标志、密码校验摘要和恢复码校验摘要；不保存明文密码或恢复码。

## IPC 安全边界

- 主进程校验 `folderPath` 为已存在目录、`fileName` 仅允许安全文件名，拒绝路径穿越。
- preload 不暴露 `ipcRenderer`，仅暴露 `saveBackupFile` 与 `selectBackupFolder`。
- Web 环境检测不到 `electronAPI` 时，使用 `Blob` 和 `<a download>` 回退。

## UI

- 设置页“数据备份与恢复”底部增加开发者与数据重置区。
- 加密导入使用独立解密 Modal，错误统一提示，不覆盖当前数据直到用户确认。
- 首次启动安全设置阻止进入工作台，完成密码与恢复码确认后才放行。
- 自动备份状态、最近备份时间、备份目录和周期在设置页可见。

## 验证

- `npm run build`
- `git diff --check`
- Electron 打包后验证目录选择、静默写入和 Web 下载回退。
- 使用测试数据验证 500 人注入、Mock 清理、恢复出厂及加密备份解密失败保护。
